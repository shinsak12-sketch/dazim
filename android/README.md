# 만화 바로가기 (안드로이드)

서버 없이 폰 안에서만 동작하는 앱입니다. Vercel·Neon 없이도 그대로 씁니다.

## 왜 앱인가

웹으로는 못 하는 두 가지가 됩니다.

| | 웹 (iframe) | 안드로이드 WebView |
|---|---|---|
| 사이트의 삽입 차단(`X-Frame-Options`) | 빈 화면 | 최상위 탐색이라 **적용 안 됨** |
| 지금 몇 화 보는지 | SecurityError | `doUpdateVisitedHistory` 로 **읽힘** |
| 주소 막힘 감지 | 추측만 가능 | `onReceivedError` 로 **정확히 감지** |

그래서 사이트가 앱 안에서 제대로 열리고, 지금 보고 있는 회차를 `저장` 버튼 하나로 잡아둘 수 있습니다.

## 동작

**회차**는 다음 화로 넘어가면 알아서 저장됩니다. 실제로 그 페이지를 열었다는
사실이라 추측이 아니기 때문입니다. (`⋮` 에서 끌 수 있습니다.)

**주소 번호**는 앱이 절대 스스로 바꾸지 않습니다. 막혔을 때 다음 번호가 맞는지는
추측일 뿐이고, 틀리면 되돌리기가 번거롭기 때문입니다.

```
목록에서 [열기]
  └─ WebView 로 만화 페이지를 직접 로드 (iframe 이 아니라 삽입 차단이 적용되지 않음)
       ├─ 다음 화로 넘어감 → "63화 저장" (자동)
       └─ 페이지를 못 불러옴 → 안내만 뜨고 아무것도 바꾸지 않음
             └─ [주소 +1] [번호 입력] [다시 시도] 중 직접 선택
```

### 새 회차 확인

목록 화면의 `새 회차 확인` 을 누르면 저장된 만화 전부를 한 번에 확인합니다.
하나씩 열어볼 필요가 없습니다.

보던 페이지를 받아서 **다음 화로 가는 링크가 있는지**만 봅니다.
뷰어 하단의 오른쪽 화살표가 곧 그 링크입니다. 만화 한 편당 요청 한 번이면 끝납니다.

`(총93화)` 같은 개수 표기는 **쓰지 않습니다.** 0화가 있는 작품은 개수와 회차 번호가
어긋나기 때문입니다 — 92화가 마지막인데 총93화로 적힙니다. 개수를 최신 회차로
읽으면 있지도 않은 93화가 있다고 판단하게 됩니다.

링크를 못 찾으면 다음 회차 주소를 직접 열어보는 것으로 한 번 더 확인합니다.
이때 상태 코드만 믿지 않습니다. 없는 회차에 404 대신 200과 안내 페이지를 주는
사이트가 있어서, 본문에 그 회차 번호가 있는지까지 봅니다.

결과는 카드에 표시됩니다.

| 표시 | 뜻 |
|---|---|
| `새 회차 · 281화 보기` | 다음 화가 나왔음. **누르면 바로 이동** |
| `최신` | 다음 화가 아직 없음 |
| (없음) | 아직 확인 안 함 |

### 상단 바

| 버튼 | 하는 일 |
|---|---|
| `목록` | 목록 화면으로 나감 |
| 제목 | 저장된 회차 / 지금 보고 있는 주소. 다르면 노란색으로 경고 |
| `저장` | 지금 보는 주소의 **번호와 회차를 한꺼번에** 저장 |
| `주소+1` | 번호를 1 올리고 다시 불러옴 |
| `⋮` | 새로고침 · 번호 내리기 · 번호 직접 입력 · 회차 자동 저장 켜기/끄기 · 브라우저로 열기 |

앞으로/뒤로 버튼은 두지 않았습니다. 사이트 하단에 이미 있고, 폰의 뒤로가기 키도
사이트 안에서 뒤로 갑니다.

`저장` 은 주소 번호까지 같이 반영합니다. 사이트가 다른 미러로 넘겨줬을 때
이 버튼 하나로 따라잡을 수 있습니다. 회차만 필요하면 자동 저장이 이미 처리합니다.

다른 작품으로 보이는 주소에서 `저장` 을 누르면 (회차 숫자 앞뒤 문자열이 다르면)
실수일 수 있으므로 먼저 확인을 묻습니다. 자동 저장도 같은 기준이라 다른 작품으로
넘어가면 북마크를 건드리지 않습니다.

### 번호를 잘못 눌렀다면

`⋮` → **주소 번호 직접 입력** 에서 원하는 번호로 바로 되돌릴 수 있습니다.
목록 화면에서도 주소를 탭하면 전체 주소를 직접 고칠 수 있습니다.

## 저장

`SharedPreferences` + JSON. 폰 안에만 있습니다.

- 두 폰 사이 동기화는 없습니다. 대신 앱이 각자 막힌 걸 감지해 번호를 맞추므로 문제되지 않습니다.
- 목록을 옮기려면 **목록 내보내기** → 카톡 등으로 전달 → 상대 폰에서 **목록 가져오기**.

## 주소 추가

세 가지 다 됩니다.

1. 크롬에서 주소 복사 → 앱의 `만화 추가` (클립보드 자동 채움)
2. 크롬에서 **공유 → 만화 바로가기**
3. 직접 입력

제목은 주소에서 자동으로 뽑습니다 (`..._266화.html` → `나 혼자 만렙 뉴비`).

## 빌드

`android/**` 를 푸시하면 GitHub Actions 가 APK를 만듭니다.
만든 APK 는 `latest` 릴리스에 올라갑니다(Actions 실행의 Artifacts 에도 남습니다).
설치 시 "출처를 알 수 없는 앱" 허용이 한 번 필요합니다.

로컬 빌드는 Android SDK가 있으면 `cd android && gradle assembleRelease` 입니다.
결과는 서명되지 않은 APK 라서 설치하려면 따로 서명해야 합니다.

## 서명 키에 대해

처음에는 `keystore/personal.jks` 와 비밀번호를 저장소에 그대로 넣어 두었습니다.
저장소가 공개라 누구나 이 앱과 같은 서명의 APK 를 만들 수 있었습니다.

그래서 v3.10 부터 새 키로 바꿨습니다(키 교체, key rotation).

- `keystore/rotated.jks.enc`: 새 키. AES-256 으로 암호화돼 있고, 암호는 저장소
  비밀 값 `SIGNING_PASSWORD` 에만 있습니다.
- `keystore/personal.jks`: 예전 키. 이미 공개돼 믿을 수 없지만, 기존 설치본 위에
  덮어쓰기가 되도록 새 키와 이어 주는 데(lineage) 씁니다.

서명은 그레이들이 아니라 Actions 에서 `apksigner` 로 합니다. 안드로이드 9 이상에서
새 키로 서명된 앱이 한 번 깔리면, 그 뒤로는 예전 키로만 서명된 APK 가 이 앱을
덮어쓸 수 없습니다. 지우고 다시 깔 필요는 없습니다.

`SIGNING_PASSWORD` 를 잃어버리면 새 키를 쓸 수 없어 앱을 지우고 다시 깔아야 합니다.
암호는 따로 적어 두세요.

## 구조

```
app/src/main/java/com/toonshortcut/app/
  SiteUrl.kt         도메인·회차 파싱/조립 (android.* 미사용 → JVM에서 테스트 가능)
  Store.kt           SharedPreferences + JSON 로컬 저장
  MainActivity.kt    목록 화면 (추가·수정·삭제·순서·백업)
  ReaderActivity.kt  WebView 뷰어 (회차 자동 저장, 주소 자동 재시도)
```

`SiteUrl.kt` 는 안드로이드 API를 쓰지 않습니다. 인코딩이 한 바이트만 어긋나도
링크가 통째로 깨지는 자리라, 순수 JVM으로 두어 SDK 없이도 검증할 수 있게 했습니다.
