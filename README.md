# 만화 바로가기

번호가 계속 바뀌는 사이트(`tkor146.com` → `tkor147.com` → …) 주소를,
주소창에서 손으로 고치는 대신 **버튼 한 번으로 갱신**하는 웹앱입니다.

## 어떻게 쓰나

1. 상단에서 이름(프로필)을 골라 목록을 엽니다.
2. 만화 목록에서 **열기** 를 누르면 새 탭으로 그 화가 열립니다.
3. 안 열리면 앱 탭으로 돌아와 상단의 **`+`** 를 누릅니다.
   번호가 1 올라가고, 목록의 모든 만화 주소가 한꺼번에 새 번호로 바뀝니다.
4. 몇 번씩 누르기 귀찮으면 **되는 번호 자동으로 찾기** 를 누릅니다.

### 자동 찾기는 어떻게 판단하나

브라우저는 보안 정책(CORS) 때문에 다른 사이트의 응답 내용을 읽을 수 없습니다.
그래서 두 군데서 나눠 확인합니다.

| 확인 주체 | 방법 | 알 수 있는 것 |
|---|---|---|
| 서버 (Vercel) | DNS 조회 + HTTPS 요청 | 그 번호의 도메인이 **개설됐는지**, 리다이렉트 최종 도착지 |
| 내 브라우저 | `fetch(mode:'no-cors')` 성공/실패 | **내 회선에서 접속되는지** |

둘 다 통과한 첫 번째 번호를 추천합니다.
사이트가 새 주소로 리다이렉트를 걸어둔 경우에는 스캔 없이 바로 그 번호를 알려줍니다.

브라우저 쪽 확인은 연결 성공/실패만 보는 것이라 100% 정확하지는 않습니다.
결과가 이상하면 목록에서 직접 번호를 골라 열어보세요.

## 회차는 어떻게 저장되나

경로 안의 숫자 자체가 진행 상황입니다. 별도 컬럼 없이 `path` 하나만 갱신합니다.

```
/나_혼자_..._266화.html   ← [다음 화] 누르면
/나_혼자_..._267화.html   ← 경로가 이걸로 바뀌어 DB에 저장됨
```

퍼센트 인코딩된 한글에는 숫자가 섞여 있어서(`%EB%82%98`의 82, `%ED%99%94`의 94)
반드시 디코딩한 뒤에 회차를 찾고, `encodeURI`로 되돌립니다.
원본과 바이트 단위로 같은 문자열이 나오는지 테스트로 확인했습니다.

회차를 넘기는 방법은 세 가지입니다.

| 방법 | 설명 |
|---|---|
| 카드의 회차 뱃지 → **다음 화** | 한 번 탭. 즉시 DB 저장 |
| **최신화 확인** | 서버가 다음 화들이 올라왔는지 확인하고 `+3화 새로 나옴` 표시 |
| 새 탭에서 보고 돌아오면 | `266화 다 보셨나요? [다음 화로]` 를 자동으로 물어봄 |

## 앱 안에서 열기 (실험적)

목록 하단 체크박스를 켜면 `열기`가 새 탭 대신 `/view/[id]` 로 갑니다.
상단 바에 `주소 +1`, `이전/다음 화` 버튼이 붙어 있어 사이트를 보면서 바로 조작할 수 있습니다.

다만 **대부분의 사이트는 iframe 삽입을 막아둡니다.** 브라우저는 차단돼도 `onload`를
부르는 경우가 있어 구분이 안 되므로, 서버에서 응답 헤더(`X-Frame-Options`,
CSP `frame-ancestors`)를 직접 읽어 판정하고 막혀 있으면 배너로 알려줍니다.

그리고 **iframe으로 열어도 회차 추적은 안 됩니다.** 크로스 도메인 iframe은
안에서 사용자가 어디로 이동했는지 읽으면 브라우저가 SecurityError를 던집니다.
회차는 위의 버튼으로만 저장됩니다.

## 프로필 (로그인 없음)

설치형 안드로이드 앱을 함께 쓰는 전제라 로그인을 두지 않았습니다.
상단에서 이름을 눌러 목록을 전환합니다. 비밀번호가 없고 서명 없는 쿠키만 씁니다.

- **만화 목록은 프로필별로 분리**되고, **도메인 번호는 함께 씁니다.**
- 인증이 없으므로 **배포 주소를 아는 사람은 목록을 보고 고칠 수 있습니다.**
  만화 제목과 경로뿐이라 민감하지 않다고 보고 단순함을 택했습니다.

## 환경변수

| 이름 | 필수 | 설명 |
|---|---|---|
| `DATABASE_URL` | 필수 | Neon Postgres 연결 문자열 |
| `PROFILES` | 선택 | 목록을 나눌 이름들. 미설정 시 `남편,아내` |

배포 후 `/api/health` 를 열면 DB 연결 상태를 확인할 수 있습니다.

## 개발

```bash
npm install
cp .env.example .env.local   # 값 채우기
npm run dev
```

테이블은 첫 DB 접근 시 자동 생성됩니다 (`src/lib/db.ts`의 `ensureSchema`).
스키마 원본은 `db/schema.sql` 에 있습니다.

## 구조

```
src/
  lib/
    site.ts              도메인·회차 파싱·조립·검증 (클라이언트/서버 공용)
    probe.ts             서버 외부 요청 공용 유틸 (SSRF 방어 포함)
    profile.ts           로그인 없는 목록 전환
    db.ts                Neon 접근 + 스키마 자동 생성
  app/
    page.tsx             목록 (서버에서 초기 데이터 로드)
    ComicList.tsx        목록 UI 본체
    api/
      profile            목록 전환
      domain             번호 조회·변경 (공용)
      comics             만화 CRUD + 순서 (계정별)
      probe              도메인 번호 후보 서버 확인
      episode            다음 회차들이 올라왔는지 확인
      embed-check        iframe 삽입 허용 여부 헤더 판정
      health             환경변수·DB 점검
    view/[id]/           앱 안에서 열기 (iframe + 상단 조작 바)
```

## 보안 메모

`probe` API는 서버가 외부로 요청을 보내므로 SSRF에 주의해서 만들었습니다.

- 클라이언트는 호스트명을 직접 보낼 수 없습니다. **저장된 패턴으로 서버가 조립**합니다.
- DNS 조회 결과가 사설·루프백·링크로컬 대역이면 요청하지 않습니다.
- `https`만 사용하고, **응답 본문은 반환하지 않습니다** (`<title>` 80자만).
- 한 번에 20개까지, 요청당 7초 타임아웃.
